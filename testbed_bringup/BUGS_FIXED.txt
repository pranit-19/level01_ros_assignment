Bug #1 — Map YAML referenced a nonexistent image

Location:
testbed_bringup/maps/testbed_world.yaml

Symptom:
The supplied map YAML referenced wrong_path_testbed_world.pgm, which does not
exist in the repository. Nav2 map_server cannot load that image.

Root Cause:
The image field contained an incorrect filename.

Fix:
Changed image to testbed_world.pgm. The relative path is resolved from the map
YAML directory by map_server.

Verification:
STATIC CONFIRMATION: testbed_world.pgm exists beside the YAML and the previous
filename does not. NEEDS LOCAL VERIFICATION: launch map_server on ROS 2 Humble.

Location:

testbed_bringup/maps/.

Bug #5 — Invalid xacro executable substitution in robot description launch

Location:
testbed_description/launch/robot_description.launch.py

Symptom:
Launching testbed_full_bringup.launch.py failed with an executable lookup error
containing a TextSubstitution object instead of the xacro executable name.

Root Cause:
FindExecutable(name="xacro") was incorrectly wrapped in PathJoinSubstitution.

Fix:
Use the direct Command invocation `xacro <testbed.xacro path>`.

Verification:
RUNTIME CONFIRMATION: after this fix and installing xacro, the starter Gazebo
and RViz simulation launched successfully.

Bug #6 — xacro runtime dependency was not declared

Location:
testbed_description/package.xml

Symptom:
The starter launch required xacro, but rosdep did not install it and launch
failed with "No such file or directory: 'xacro'".

Root Cause:
The package manifest omitted its direct xacro runtime dependency.

Fix:
Added <exec_depend>xacro</exec_depend>.

Verification:
RUNTIME CONFIRMATION: ros-humble-xacro was installed and the robot description
launch subsequently started.
------------------------------------------------------------

testbed_gazebo/package.xml
